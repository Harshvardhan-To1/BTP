## 2. Verified problems

Ordered by severity for the evaluation.

1. **Missing source package.** `src/` absent; Exp1-4 and the notebook fail on
   the first import. Verified by `git ls-files`, `git log --all`, and the
   remote branch list.
2. **Inverted functional-split bandwidth model (ACAFS).** The docs report
   "BW reduction vs *fixed Split 6*" with 7.2x < 7.1 < 6 in bandwidth. In
   3GPP TR 38.801 / O-RAN terms, split 6 (MAC-PHY) carries transport blocks
   and is by far the *cheapest* of the three on the fronthaul; the I/Q splits
   (7.x) are the expensive ones. The headline "33 % saving vs split 6" is
   therefore not meaningful.
3. **Fake "fast rank estimate" curve in Exp3.** `exp3_acafs_gain.py` line 53
   built the "fast" curve as `exact_rank + random_integers(-1, 2)`. It is not
   an estimator. The committed figure shows this curve flat at 55 % while the
   exact curve steps 0 % -> 75 %, and the "Theorem 5 bound" (33 %) sits below
   both, so it was not a bound either.
4. **Unfair SVD baseline in Exp2.** Committed Fig. 2 shows SVD at ~1.7 s for a
   64 x 1200 matrix; an economy SVD of that size takes ~13 ms on this machine
   (measured). The baseline must have used the full N x N SVD. The notebook
   output (18-30 ms) contradicts the figure too. The "4-6x faster than SVD"
   claim was built on this.
5. **O(MN) reference line plotted in wrong units** (seconds vs ms) in Exp2,
   sitting three decades below the data.
6. **NMSE metric conflates discarded noise with distortion.** Truncating
   encoders (CSEE, SVD, RAS-BFP) are measured against the *noisy* received
   matrix, so their NMSE saturates at about -SNR dB. The committed Fig. 4
   shows exactly this (NMSE tracks -SNR), yet the slide text claims the
   encoders are "stable across the full SNR sweep". Interpretation was wrong,
   and no signal-domain metric existed.
7. **CSEE's delay-domain sparsity assumption does not hold for data-bearing
   symbols.** Reconstructing the channel model with random QPSK per subcarrier
   gives CSEE -0.5 dB at K = 24 (useless), because `Y = H diag(X)` whitens the
   delay domain; the committed -18 dB figure is only obtainable on reference
   symbols de-rotated by the known sequence. The original code must have used a
   constant pilot, i.e. an unrealistic traffic assumption. (Spatial low rank
   *does* survive modulation, since `diag(X)` is invertible.)
8. **Compression ratios referenced to 32-bit components.** The docs quote BFP
   b = 8 at ~3.9x; against the 16-bit uncompressed I/Q width used by
   eCPRI/O-RAN it is ~2.0x. All original CRs are inflated ~2x.
9. **InverseNet-Ultra NumPy engine used ReLU while the trained model uses
   GELU** (`matinv_bench/inversenet.py`). Effect is small because the
   hyper-network weights are tiny (0.36 % output difference at n = 10) but it
   is a correctness bug. Its docstring also claimed "float32 precision (~1e-7)
   ... outperforming LU in latency"; committed results show ~1e-6 error and
   slower-than-LU medians.
10. **Documentation overstatement.** "Theorems 1-5" with no proofs or code,
    "100 MHz, 15 kHz SCS" with N = 1200 subcarriers (1200 x 15 kHz = 18 MHz),
    "IEEE TWC/JSAC target", and a roadmap (AVX-512/CUDA kernels, RIC xApp, USRP
    OTA) unrelated to anything implemented.

## 3. Missing evidence (claims that could not be validated)

* Any number in `docs/mid_evaluation_report.md` section 4 (NMSE, CR, encode
  time, "4-6x faster than SVD") - the generating code is absent.
* "Theorems 1-5": no statements or proofs exist beyond one-line formulas in
  the docs; the RAS-BFP "Theorem 2" formula quotes a generic (1 + eps_r)
  factor without saying what eps_r is.
* The matrix-inversion benchmark's dim-500 numbers were produced on a
  different host and with 1000 samples; only 100 samples were regenerated here
  (disk), so dim-500 timings in the new run use 20 held-out matrices.
* The notebook outputs were produced by code that no longer exists.
